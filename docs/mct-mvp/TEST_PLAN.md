# 初步测试计划：三人跨昼夜旅行

状态：计划草案。RFC #2 Phase 0 的真实 Mindcraft telemetry 接入、Phase 1 单 agent Fabric 观察切片和独立真实 Pathfinder harness 已完成；当前仍需把同一事件链接到真实 Mindcraft agent，再勘察路线和开展自主旅行。以普通 Minecraft 世界为测试基线；Tellus 是可选世界生成方案，与 Mindcraft 没有依赖要求。此前的 Tellus 连接检查只保留为历史结果。

## 优先讨论：观测与可恢复暂停

已确认范围：首版只支持同次运行内暂停、观察和继续，不要求关闭程序后恢复。当前 Fabric 观察切片已能显示遥测轨迹，但暂停屏障和完整事件浏览仍未实现或运行验证。

详细的记录格式、轨迹、时间线和暂停屏障见 [过程记录与可视化 MVP](OBSERVABILITY.md)。

- 画面：复用真实 Minecraft 旁观客户端作为现场画面；核心观测改为轨迹、事件时间线和决策详情，不把旁观视角当作完整可视化。
- 状态：复用已有 MindServer 面板中的位置、生命、食物、背包、活动和消息。建议补充三人的共同目标、饱和度、世界时间、有效运行时长和全局运行状态；这些新增字段尚未实现。
- 记录：保留带时间和角色名的交流、实际执行的动作及成功/失败结果，便于对照画面理解过程；不把角色生成的解释等同于真实内部推理。
- 控制：第一版采用三人整体暂停/继续。角色进程和游戏连接保留，暂停期间能看画面、状态和历史；旁观相机可移动，观察者不改变测试世界。
- 暂停含义：世界演进与三人的模型调用入口、消息处理、自主循环、动作及自动模式都进入暂停状态。需要覆盖机器人自身的玩家物理与生存状态，不能只停止输入。仍在返回的模型结果不得执行；已发出的请求可能仍产生费用。暂停边界前已收到的消息保留，并在恢复时按原顺序处理。
- 恢复含义：同一次运行中保留目标、对话与队伍状态；恢复后重新观察，再继续目标。被中断的挖掘或寻路可重算，不要求从同一执行指令续跑。动作超时、对话计时和测试时长不累计暂停时间。
- 界面需区分运行中、暂停中、已暂停和恢复中，只有世界和三个角色都确认暂停才显示“已暂停”；未成功时显示实际状态。
- 跨进程关闭后恢复已明确不纳入首版；现有重启按钮不属于本次暂停流程。

代码核对：已有 `getFullState` 和 MindServer UI；`render_bot_view` 可开启 Prismarine Viewer。`stop-agent` 最终发送 SIGINT 结束进程；`SelfPrompter.pause()` 只控制部分行为，idle 回调还会恢复自动模式，均不是完整的测试暂停。

版本选择尚待讨论：现有环境为 1.20.1。原版 `/tick freeze` 从 1.20.3 引入，且不冻结玩家，因此即使采用更新版本，也需单独约束作为玩家连接的机器人。保留 1.20.1 时需评估服务端冻结扩展，先验证其玩家物理和计时覆盖，再决定实现。依据：[Mojang 1.20.3 发布说明](https://www.minecraft.net/en-us/article/minecraft-java-edition-1-20-3)。

## 任务

MCT_A、MCT_B、MCT_C 从 A 出发前往 B，全员存活抵达。途中至少经历一次过夜，并在出现实际食物需求时处理进食与补给。不预先指定领队、采集者或建造者。

距离由路线勘察决定，不采用“十分钟路程”作为目标。路线要足够支撑跨昼夜行程，并包含一两个有意义的选择，如翻越山地还是绕行、走水边还是找较安全的通道。三人都到达、过夜情况和进食覆盖分别记录。

## 首轮条件

- 普通 Minecraft Java 生存世界，固定种子；版本随暂停方案确定，现有 1.20.1 仅为可复用设施。无需安装 Tellus。
- 生存、普通难度、自然昼夜、敌对生物生成开启、自然回血开启。
- 三人共享目的地和同行者姓名，基础能力相同，初始物资相同。保持原有自保与执行机制。
- 起始物资草案：每人石斧、石镐、4 原木、2 面包、4 火把，不预配床和全套装备；待确认。
- 正式启程前对齐清晨、生命、食物、饱和度和物品；启程后不传送、不补发食物、不设白天、不人工挪开障碍。观测暂停需要记录且不计入有效时长。环境故障时停止并保留记录。
- 首轮建议选择 `full-night`，完整经历夜晚以观察生存应对；场景配置仍保留待确认状态。允许自行制作床并跳夜，可以体现筹备能力，但不能证明完整夜间的风险应对。
- 地图资源、动物/敌对生物实际生成和路线可生存性需要勘察确认；“配置开启”不等于实际存在。

## 顺序

### 0. RFC #2 Phase 0 事件接入

已完成被动事件信封、MindServer 统一 JSONL 记录、agent 侧来源接入、单 agent Fabric 观察切片和独立真实 Pathfinder harness。烟测覆盖 schema、稳定 ID、决定到动作的父 ID、MindServer 桥接和 JSONL 写入；真实普通世界已验证目标、计划路径、实际位置采样和 `goal_reached`，客户端已验证真实路径线绘制，尚未验证真实 Mindcraft agent 的连续旅行。

### 0b. 单 Agent 真实 MC 观测验收（当前步骤）

使用 `npm run mct:single-agent-observer-check`，保持普通 MC 世界与 `MCT_A` 一名脚本 Agent；任务和中断由脚本规定，没有 LLM 调用。

1. 观察行进时实际青色连续带与白色计划箭头，HUD 的角色数必须为 1。
2. 首次抵达后计划点数归零，保留实际轨迹，目标标为已抵达。
3. 返回途中移动 3 方块后由脚本中断，旧目标标为中断，旧计划清除。
4. 在 `I` 面板查看指令、动作和结果；通过上游/后续按钮核对稳定 ID，脚本来源必须明确。
5. 改令后再次抵达；JSONL 中所有关联 ID 可解析，结果为 arrived / interrupted / arrived。
6. 客户端保持在线，启动另一个 run_id，确认旧序号较大时仍能接到新运行；旧目标、轨迹、历史与选择自动清空。空运行中无旧 Agent。
7. `B` 简化视图隐藏轨迹和空间标记；恢复后查看连接状态。关闭记录服务只改变观察连接状态，不给 Agent 发送控制。

每阶段 Enter 仅推进脚本，不冻结世界，不能当作暂停验收。此场景主动设为白天，使用约 60 方块的短路线，只验收观察链，不验证过夜/饥饿/合作。GoalNear 的容差为 2 方块，抵达不要求坐标完全重合。

### 0a. 脚本 agent 观测演示

已完成一个无 LLM、无 Minecraft、无 Tellus 依赖的三个脚本 agent 演示：它生成三条轨迹、决策、消息、动作、食物和昼夜事件，并支持同次运行暂停/继续。它只验收观测层，不证明真实寻路或生存行为。

### 1. 先完成观测与暂停方案，再检查普通世界环境

下一步把同一 telemetry 事件链接入一个真实 Mindcraft agent，检查 Pathfinder 计划路径、实际位置采样、状态和消息能否连续进入观察端；随后再检查服务端、三机器人连接和暂停期间世界、玩家状态、动作、消息及模型任务是否受控，恢复后能否延续共同目标。当前尚未运行真实 Mindcraft 旅行和暂停检查；脚本 harness 只证明 Minecraft/Pathfinder 侧链路。

### 2. 路线与资源勘察

在普通世界选择 A/B 和中途可用资源，查看高度、地形、危险与可行走法。路线应支撑至少一晚的自主旅行；如提前抵达，不靠要求原地等待来声称路线覆盖了过夜，需调整场景。

### 3. 一次完整三人试跑

先约定模型、时长和费用上限。只提供共同任务；记录路线选择、夜间准备、遇险处理、食物需求、进食和重聚。观察者仅观看，不指挥角色。如果运行上限到达而任务未结束，记录未完成，不自动追加预算。

### 4. 按实际卡点补最小功能

优先区分：地形/协议故障、技能缺失、模型决策失误、通信限制。若单一交谈对象确实阻碍三人协作，再做最小多人消息适配；若主要问题是寻路，则先处理当前路线所需能力。修复后复跑同一场景，不一次改变多个条件。

## 怎么看结果

只需一段录像/观察记录、一份运行日志和一页复盘：

| 项目 | 看什么 |
| --- | --- |
| 到达 | 三人的真实位置进入 B 附近，注明是否有人死亡、复活或掉队 |
| 过夜 | 记录入夜、应对和天亮；注明睡眠跳夜、完整经历或未覆盖 |
| 食物 | 记录实际 food/saturation 变化、消耗的食物、获取/分享过程；未触发则写未覆盖 |
| 合作 | 至少记录具体交流如何改变行动或帮助同伴；三人独立到达不直接算协作成功 |
| 连续性 | 次日是否继续原目标，是否反复邀约、停工聊天或来回改计划 |

Mindcraft 默认加载 `mineflayer-auto-eat`，并有自保、战斗、狩猎等自动模式。自动吃掉背包里的面包证明执行机制有效，不能单独证明 LLM 主动发现饥饿。复盘时分开记录自动执行与角色主动决定的获取、储备、分享和路线调整。

当前不承诺专门的长期记忆、稳定多人对话、全天直播或自然分工已经具备。第一轮要回答的是：三人能否在实际旅行和生存需求中持续推进共同目标，以及最先阻碍它的因素是什么。

### 0c. 第一阶段集成回归

先运行不需要模型的检查：

```powershell
npm run mct:runtime-config-smoke
npm run mct:telemetry-smoke
npm run mct:agent-telemetry-smoke
npm run mct:telemetry-bridge-smoke
npm run mct:state-collection-smoke
npm run mct:telemetry-performance-smoke
& 'D:\workshop\Game\Tellus-Optimized-rfc\gradlew.bat' -p client/observatory build stateSmoke --no-daemon --offline -I D:/workshop/_tmp/owo-local.init.gradle
```

`state-collection-smoke` 验证单个 Agent 回调超时不会拖住采集，并验证恢复后保留嵌套完整状态。`stateSmoke` 验证嵌套快照、世界 tick 与日内时间区分、Y/跳变轨迹断段和旧目标隔离。性能 smoke 只给同步 JSONL 的合成基线，不能替代真实服务器运行。

需要真实 MC 的检查单独运行：

```powershell
$env:MCT_RUNTIME_PROFILE = 'observatory'
npm run mct:single-agent-observer-check
```

需要自动化推进检查点时可设置 `$env:MCT_AUTO_CONTINUE = '1'`；默认不设置时仍可逐个 Enter 观察。它验证普通世界、单个脚本 Agent、观察客户端和运行隔离；不验证 LLM、过夜、饥饿或完整暂停。真实 Mindcraft Agent 仍需已授权的模型和 embedding 配置，当前缺少 `config/mct-mvp/model.local.json`，因此不能宣称真实 LLM 闭环已通过。生存 profile 已准备好，启动前还需确定 A/B 坐标、起始物资和 `sleepPolicy`；启动器默认连接 `ordinary-survival-1.20.1`，不会连接历史 Tellus profile。
